The Cyber Kill Chain: How Attacks Actually Happen

📅 August 20, 2026 ⏱️ 20 min read 🏷️ Beginner 👤 Your Name
#kill-chain #framework #defense #cybersecurity #infosec
⚠️ EDUCATIONAL DISCLAIMER

This guide explains attack frameworks from a defensive perspective. Understanding how adversaries operate is essential for building effective detection and response capabilities. Never practice attack techniques on systems you do not own or have explicit written permission to test.

Why the Kill Chain Matters

Every cyberattack — from a script kiddie running automated scans to a nation-state APT — follows a pattern. The Cyber Kill Chain, developed by Lockheed Martin in 2011, breaks that pattern into seven stages. If you understand the stages, you can break the chain at any point and stop the attack.

This is not just theory. SOC analysts, incident responders, and threat hunters use this model every day to:

  • Map detected events to attack stages
  • Identify which defenses failed and which worked
  • Prioritize security investments where they matter most
  • Communicate incidents clearly to non-technical stakeholders

The 7 Stages of the Cyber Kill Chain

Stage What Attackers Do What Defenders Do
1. Reconnaissance Gather information about the target Minimize public footprint, monitor for scans
2. Weaponization Combine exploit + payload into deliverable Threat intel, signature development
3. Delivery Transmit weapon to target (email, USB, web) Email filtering, web proxies, USB controls
4. Exploitation Trigger vulnerability to execute code Patch management, exploit mitigation
5. Installation Establish persistence (backdoor, service) EDR, integrity monitoring, least privilege
6. Command & Control (C2) Communicate with attacker infrastructure Network monitoring, DNS filtering, beacon detection
7. Actions on Objectives Exfiltrate data, deploy ransomware, etc. DLP, encryption, segmentation, logging
📝 Key Insight

An attacker must complete all seven stages to achieve their goal. A defender only needs to break one stage to stop the entire attack. This asymmetry is the defender's advantage.

Stage 1: Reconnaissance

Before attacking, the adversary learns everything they can about the target. There are two types:

Passive Reconnaissance

Gathering information without directly interacting with the target. The target has no idea it's happening.

  • WHOIS lookups — domain registration details, name servers
  • DNS enumeration — subdomains, MX records, SPF records
  • OSINT (Open Source Intelligence) — LinkedIn, company websites, press releases
  • Shodan / Censys — find internet-facing devices and services
  • Google Dorks — advanced search operators to find exposed files, login pages, error messages

Active Reconnaissance

Directly interacting with the target's systems. This can be detected.

  • Port scanning — Nmap, Masscan to find open ports
  • Service enumeration — banner grabbing, version detection
  • Vulnerability scanning — Nessus, OpenVAS
  • Social engineering — phishing emails, phone calls, physical visits

How to Break This Stage

Defense How It Works
Attack Surface Reduction Remove unnecessary services, close unused ports, use private WHOIS
Honeypots Deploy fake systems to detect and analyze reconnaissance activity
Threat Intelligence Subscribe to feeds that list known malicious IPs scanning the internet
Employee Training Teach staff to verify unusual requests and not overshare on social media

Stage 2: Weaponization

The attacker creates a deliverable weapon. This usually means combining:

  • An exploit — code that triggers a vulnerability
  • A payload — the malicious action (reverse shell, keylogger, ransomware)
  • A delivery mechanism — Word macro, PDF, executable, script

Common Weaponization Techniques

Technique Description
Office Macros Malicious VBA in Word/Excel that downloads payload when enabled
PDF Exploits Embedded JavaScript or malformed objects triggering reader vulnerabilities
Script-Based PowerShell, Python, or JavaScript scripts that execute in memory
Exploit Kits Automated web platforms that serve exploits based on browser fingerprint
Living Off The Land Using legitimate system tools (PowerShell, WMI, certutil) for malicious purposes

How to Break This Stage

  • Macro blocking — Group Policy to block macros from internet-originated files
  • Application allowlisting — Only approved executables can run (AppLocker, WDAC)
  • Threat intelligence — IOC feeds for known malicious file hashes
  • Script execution policies — Constrained Language Mode for PowerShell

Stage 3: Delivery

The weapon is transmitted to the target. This is where the attack crosses the perimeter.

Common Delivery Vectors

Vector Example
Phishing Email Spear-phishing with malicious attachment or link
Watering Hole Compromising a website the target frequently visits
USB Drop Leaving infected USB drives in parking lots (HID attacks, autorun malware)
Supply Chain Compromising software vendor to distribute trojanized updates
Malvertising Malicious ads on legitimate websites redirecting to exploit kits

How to Break This Stage

  • Email security gateways — SPF, DKIM, DMARC, sandboxing attachments
  • Web filtering — Proxy with URL categorization, SSL inspection
  • USB port controls — Disable or restrict removable media
  • User awareness training — Phishing simulations, reporting procedures

Stage 4: Exploitation

The weapon triggers a vulnerability to execute code on the target system. This is the moment the attack becomes technical.

Types of Exploitation

  • Software vulnerability — Buffer overflow, use-after-free, SQL injection
  • Configuration weakness — Default passwords, exposed admin panels
  • Human vulnerability — User enables macro, clicks link, enters credentials
  • Zero-day — Unknown vulnerability with no patch available

How to Break This Stage

Defense How It Works
Patch Management Rapid deployment of security updates (target: critical patches within 24-48 hours)
Exploit Mitigation ASLR, DEP, CFG, EMET/Windows Defender Exploit Guard
Browser Isolation Remote browser execution prevents web exploits from reaching the endpoint
Application Sandboxing Restrict what applications can access (AppContainer, SELinux, AppArmor)

Stage 5: Installation

The attacker establishes persistence — a way to maintain access even if the system reboots or the user logs out.

Common Persistence Mechanisms

Mechanism Location / Method
Registry Run Keys HKLM\Software\Microsoft\Windows\CurrentVersion\Run
Scheduled Tasks Task Scheduler with hidden or disguised entries
Services Creating new Windows services that auto-start
Startup Folders %APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup
WMI Event Subscriptions Trigger actions based on system events (fileless persistence)
Bootkits / Rootkits Modify bootloader or kernel for pre-OS persistence

How to Break This Stage

  • EDR (Endpoint Detection & Response) — Monitors for suspicious process creation, registry changes, service installations
  • File Integrity Monitoring (FIM) — Alerts when critical files/registry keys change
  • Least Privilege — Standard users cannot install services or modify system registry
  • Application Control — Only approved software can execute
💡 Defensive Insight

Most persistence requires administrator privileges. Running as a standard user (not admin) for daily work breaks multiple kill chain stages automatically.

Stage 6: Command & Control (C2)

The compromised system communicates back to the attacker's infrastructure. This is the "phone home" stage.

How C2 Works

Once installed, malware needs a way to receive commands and send data. Common C2 channels:

  • HTTP/HTTPS — Blends with normal web traffic, hard to distinguish
  • DNS — Encodes data in DNS queries (DNS tunneling)
  • Social media / Cloud services — Uses Twitter, GitHub, Pastebin, Google Docs as dead drops
  • Email — Commands sent via email, responses in drafts
  • ICMP / Custom protocols — Lower-level network protocols

C2 Indicators

Indicator Description
Beaconing Regular, timed connections to external IP (e.g., every 60 seconds)
Unusual DNS Queries High volume of queries to rare domains, long subdomain names (data exfiltration)
Long-Lived Connections HTTPS connections lasting hours from non-browser processes
Domain Generation Algorithms (DGA) Malware generates thousands of random domains daily; only a few are real C2 servers

How to Break This Stage

  • DNS filtering — Block known malicious domains, sinkhole DGA traffic
  • Network segmentation — Limit which systems can reach the internet
  • Proxy inspection — Decrypt and inspect HTTPS traffic for anomalies
  • Behavioral analysis — Detect beaconing patterns, unusual connection timing
  • Host-based firewall — Block outbound connections from unexpected processes

Stage 7: Actions on Objectives

The attacker achieves their goal. This is the "payoff" stage.

Common Objectives

Objective What Happens
Data Exfiltration Stealing intellectual property, customer data, credentials, emails
Ransomware Deployment Encrypting files and demanding payment for decryption keys
Cryptomining Using victim's computing power to mine cryptocurrency
Lateral Movement Spreading to other systems in the network to expand access
Destruction Wiping disks, corrupting data (wiper malware)
Espionage Long-term silent access for intelligence gathering

How to Break This Stage

  • Data Loss Prevention (DLP) — Monitor and block unauthorized data transfers
  • Encryption at rest — Even if data is stolen, it's unreadable without keys
  • Network segmentation — Prevent lateral movement with VLANs, micro-segmentation
  • Comprehensive logging — Every action leaves an audit trail for investigation
  • Incident response plan — Predefined playbooks for containment and recovery

MITRE ATT&CK: The Modern Evolution

The Cyber Kill Chain is excellent for high-level strategic thinking, but modern defenders often use MITRE ATT&CK for tactical, detailed analysis.

Framework Focus Best For
Cyber Kill Chain Attack stages, strategic defense Executive briefings, investment decisions, high-level IR
MITRE ATT&CK Specific techniques, tactics, procedures (TTPs) Detection engineering, threat hunting, purple teaming

MITRE ATT&CK maps hundreds of specific techniques (like T1059.001 for PowerShell) to tactics. As you advance, you'll use both frameworks together: Kill Chain for "where are we in the attack?" and ATT&CK for "what specific technique did they use?"

🔗 Resource

Explore the full MITRE ATT&CK framework at attack.mitre.org. It's free, open, and constantly updated by the security community.

Hands-On Exercise: Map a Real Incident

Let's practice using the Kill Chain with a simplified version of a real attack.

Scenario: The ACME Corp Breach

An attacker compromised ACME Corp and stole customer data. Here's what investigators found:

  1. Attacker found ACME's email format from LinkedIn profiles (Reconnaissance)
  2. Crafted a Word document with a malicious macro that downloads a backdoor (Weaponization)
  3. Sent spear-phishing email to HR manager with the document (Delivery)
  4. HR enabled macro; macro exploited Office vulnerability to run PowerShell (Exploitation)
  5. Backdoor created a scheduled task to run every boot (Installation)
  6. Backdoor connected to evil-c2.com every 5 minutes via HTTPS (C2)
  7. Attacker used stolen credentials to access CRM database and exfiltrated 50,000 records (Actions on Objectives)

Your Task

For each stage, identify one defensive control that could have broken the chain:

Stage Potential Break Point
Reconnaissance Limit employee LinkedIn details; use generic email formats
Weaponization Block macros from internet-originated files via Group Policy
Delivery Email gateway with attachment sandboxing
Exploitation Keep Office fully patched; use Application Guard
Installation EDR detecting scheduled task creation; standard user accounts
C2 Proxy inspection; DNS filtering of unknown domains
Actions on Objectives DLP monitoring database access; encryption of customer records
🛡️ Key Takeaway

Notice how multiple defenses could have stopped this at every stage. Defense in depth means not relying on a single control — if email filtering misses it, EDR catches it. If EDR misses it, DLP stops the exfiltration.

Summary: The Defender's Advantage

Stage Attacker Must... Defender Can...
Reconnaissance Find something useful Minimize footprint, detect scanning
Weaponization Build undetectable malware Use threat intel, block known signatures
Delivery Get past email/web filters Layered filtering, user training
Exploitation Find unpatched vulnerabilities Patch rapidly, harden configurations
Installation Establish stealthy persistence Monitor critical locations, use least privilege
C2 Maintain covert communication Inspect traffic, detect anomalies
Actions Complete mission without detection Log everything, encrypt data, segment network
